# prove-visual-change：视觉改动的像素证据

> 原子范围：只负责"证明界面真的变成想要的样子"，不改逻辑。
> **[L0] 用户已两次拒绝"几何达标"口径**：SVG 几何全对但没设 stroke 会整条不可见。只报"代码改了"不算验证。

## 步骤

1. **起服务**：`start.bat`（默认 8000，被占自动顺延到 8009，`start.bat:22-23,127-141`），隐藏 PowerShell 会轮询 `/healthz` 到 200 才开浏览器（`:159`）。已有实例就复用，别另起端口。
2. **真人路径**：browser-use 打开目标页面，用点击/拖拽/滚动/键盘走一遍用户流程；**程序化 `focus()`、`dispatchEvent` 不算人手**。至少覆盖：主路径、边界（375px 不横向溢出、触控目标 ≥44px）、键盘可达与焦点可见、弹窗 `Esc` 与焦点还原。
3. **截图存档**：关键态各截一张，落 `.system_generated/<场景>/<tag>/`；同时记录视口尺寸。
4. **像素证据**：`.venv/Scripts/python.exe tools/pixel_scan.py <png>` 按 PAPER/CARD/DARK 归类打印行段（`:100-115`）——用它证明"某条线/某个框真的在某个 y 区间有色值"。
   - **[L1] `pixel_scan.py` 无判定、恒 rc=0**：它是素材，不是门禁；结论要自己写在证据里。
5. **性能类改动**：`render-ms` 只算同步渲染段，**不许冒充全卷耗时**；A4 视口级虚排必须**逐页滚过再量**，否则得到假阴性（先例：军令 #18 前 3.58s→245ms）。
6. **布局量测坑**（逐条踩过）：
   - 量 50/50 分栏要扣掉 grid gap，别拿容器宽度对半当结论
   - `ResizeObserver` 重绘会把切图台冲走；canvas 的 border 会让坐标偏移
   - 网格行高不锁 → 依赖滚动的逻辑全是死代码
   - `.pg-q>` 行距别挂错元素、`.pg-ansbox` 别带外边距
7. **沙箱渲染坑**：插件 CSP 会拦 `blob:`/`data:` 的 img，缩略图要画到 canvas 再取 dataURL；宿主壳资源必须 `no-store`（F5 丢功能往往是缓存而不是时序，光加 no-cache 不够）。
