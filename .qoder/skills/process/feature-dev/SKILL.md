# feature-dev — 编排调度中枢（链位2，工序02）

> 统一驱动六道工序；只管调度与四态决策，禁止产出计划文档、禁止改产物。

## 启动：记录先行 + 编排时预绑定

1. 建 biz 记录（R04 记录先行）：`sync-biz-record` 新建 `records/biz/{YYYY-MM}/{YYYYMMDD}_{需求名}.md`，[REQ] 写入用户原话与初步验收标准（后续一切断言的需求源头）
2. 读 `.qoder/skill-bank.json` 锁定角色白名单
3. 驱动 architect 在 [PLAN] 写「能力绑定」行（一次性锁定 coder 可用 domain skill）

## 六道工序（绿↓送检，橙↑不达标打回重跑）

```
- [ ] 01 意图识别  architect 读懂需求真实诉求 → checklist-01 → Eval-01 → 四态
- [ ] 02 编排规划  本角色：调度决策·分配能力（无外挂 Eval）
- [ ] 03 代码调研  architect 探索现有实现（可并行，结论并入 [PLAN]）
- [ ] 04 领域设计  architect 出 [DESIGN] → checklist-04 → Eval-04 → 四态
- [ ] 05 编码实现  coder 按绑定清单写代码 → checklist-05 → Eval-05 + reviewer 门禁 → 四态
- [ ] 06 自动化验证 test 五步验证环（做）→ checklist-06 → Eval-06（判）→ 四态
- [ ] 收尾       沉淀评估（R05 §5）→ recorder 汇总 [IMPL]/[VERIFY]/[RELEASE]，状态流转「已发布」→ recorder 用 archive-tech-report 存档报告；rule/feature 汇总文档按需同步（biz 记录为唯一事实源）
```

## 送检 checklist（防幻觉，送 Eval 前逐项核，任一不过就地打回，不消耗 Eval 轮次）

| 工序 | 核对项（依据 R05 §7 证据链） |
|---|---|
| 01 | 验收标准每条可回溯到用户原话或追问确认，无自行补充的需求 |
| 04 | 引用的存量接口/类/表/配置均带 `文件路径#符号`；兼容性与分层动线结论有代码定位或记录引用；含问题定性（点/类），类问题有泛化方案+扩展成本声明 |
| 05 | diff 涉及文件清单与实际变更一致；引用的错误码/枚举值/参考实现均已验证存在 |
| 06 | 每条执行结论（编译/测试/覆盖）附命令+原始输出，禁止转述 |
| 通用 | 无"应该/一般来说/通常"式表述；每条事实断言带三类证据之一（代码定位/命令输出/记录引用） |

## 门禁四态（读 Eval 结果决定，唯一决策点）

| 态 | 条件 | 动作 |
|---|---|---|
| 过 | Eval L0 证据核验+三层全过 + reviewer 无 Critical | 下一道工序 |
| 警告 | L2 建议项 / Suggestion | 记录理由放行 |
| 回环 | 任一层 fail / Critical | 打回执行角色，仅传结构化失败清单 |
| 转人工 | 同工序回环 2 轮仍不过 | 停止流水线，recorder 留痕 |

## 回环路由表

| 失败来源 | 回环目标 | 传递内容 |
|---|---|---|
| Eval-01 意图不清 | architect | 缺失的验收标准项 |
| Eval-04 设计缺陷 | architect | 缺陷层+原因 |
| Eval-05 / reviewer Critical | coder | 失败清单+原因 |
| Eval-06 测试不及格 | test（断言问题）/ coder（缺陷） | 按 eval 归因路由 |

## 编排约束

1. 做判分离：eval/test/reviewer 结论只读不用，不替它们判定
2. 中断恢复：以 biz 记录章节 + Eval 轮次记录为准续做
3. 范围收敛：方案外问题回 01/04，不顺手改
4. 转述即背书：向 Eval/门禁传递结论时必须同时传递证据，发现执行角色产物含无证据断言就地打回，不送检

## 收尾：沉淀评估（解决一类问题，R05 §5）

发布前逐项判定，命中即执行：

1. 本次编码动线是否可抽象为新 domain skill？→ 命中则走新增 skill 三登记（skill-bank + AGENTS.md + sys 记录）
2. 是否发现新的存量规律/先例？→ 命中则补 knowledge card 或对应 R 文件条款
3. 通用设计模式（类型码扩展等）是否值得写入 [PLAN] 供后续需求引用？
4. 均不命中：在 [RELEASE] 记一句「沉淀评估：无可复用项」，不强行沉淀

## 完成判据

01/04/05/06 四道 Eval 全过（或警告留痕）；biz 记录含 REQ+IMPL+VERIFY、状态流转「已发布」；沉淀评估已做；reports/ 报告已存档；门禁命令 + 构建命令过（以 AGENTS.md 常用命令节为准）；无未闭环回环。
