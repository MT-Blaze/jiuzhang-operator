## 一、背景

录题审核现在是「审到哪、点到入库才查哪」：命中了才在审核画布闪红灯、开对比窗、在右栏做选择，老师得在画布和对比窗之间来回跳。本轮把查重改成**进来就整批查完**，命中的题**抽进独立的重题池**，用池子自己的画布统一处理；审核画布从此只留青黛（悬停）与琥珀（有问题）两盏灯。

设计口径已拍板在 `docs/question-cutting-pipeline.md` §2，本卡只搬运执行项，不再重议产品口径。

## 二、已裁决（原「开工前必须裁决」三项，2026-11-02 结案）

1. **整页底图不拷、不用留**——池子里比的是渲染，整页底图切完就没用；题自己的成品图（题干图、选项图等）本来就跟着题走（台账第 7 条），池子跨批次存时随题留在池里，批次删了不受影响。
2. **池子跨批次存**，不跟批次走，攒着有空再处理；批次删了池里那条不受影响。
3. **池内动作四项**：**合并元数据 / 新增解析（增加来源）/ 不重复（分开存）/ 删除**。原【覆盖】与旧 UI 的【放弃】都不在列，按退役处理。

### 由四项动作推出的执行口径（按此施工；若主公另有口径，以台账为准）

- **合并元数据**：主库原题留着，只把池里这条的**元数据**并进去——来源追加、标签取并集、考向取并集（主考向仍用主库原题的）、难度仅当主库缺省时才补；**题干、选项、答案、解析、配图一个字不动**。冲突不覆盖，列出来让老师选。
- **新增解析（增加来源）**：主库原题留着，把池里这条的解析作为一种新解法接在后面，并追加来源；答案明确不同时锁死。
- **不重复（分开存）**：池里这条当**一道独立的新题**写入主库，主库原题不动；走与审核画布入库相同的校验（答案、占位符、考向），缺项不写库、留在池里并标出缺什么。
- **删除**：只删池里这条（连同它的成品图），**主库原题一个字节不动**；需二次确认。
- **答案口径**：两侧都有答案且明确不同 →「合并元数据」「新增解析」锁死；「不重复」「删除」不受影响。一方缺答案 → 前两项允许但提示。
- **不做覆盖**：两道题一模一样，没有覆盖的理由；池里四条路之外不提供「替换主库」这条路。

## 四、任务（六步）

### 第一步 · LaTeX 写法字典与清洗器（底座，纯函数）

1. 新增写法字典与清洗器（文件名与放置按 R00/R03 定），三个 AI 槽（识别、打考向、解题）共用。
2. 字典只收**同一记号体系内的同义写法**：`\dfrac`/`\tfrac`→`\frac`、`\leq`/`\leqslant`→`\le`、`\geq`/`\geqslant`→`\ge`、`\neq`→`\ne`、`x^2`→`x^{2}`、`\frac12`→`\frac{1}{2}`、各种长相互异的减号（U+2212／全角／连字符）→ `-`。
3. **绝不合并「长得像但含义不同」的**：`\times` 与 `\cdot`、`\{\}` 与 `()` 与 `[]` 各自保留；`\left\right` 影响渲染，写库清洗**不碰**。
4. 两条入口分开：**写库清洗**（改正文，保守）与**比对归一**（只算指纹，可忽略 `\left\right`／间距／空格，不改原文）。
5. 硬条件：按 LaTeX 命令切词改（不做字符串替换）、幂等（洗十遍＝洗一遍）、不认识就不动并记录、每条规则配正例/反例测试。
6. 范围：只洗 AI 新写的字；老师手打/粘贴的原样保留；库里已有的题不改正文，比对时洗副本。
7. **与军令 #31 合并成一套**：#31 已有单题「清洗当前题 LaTeX」＋强制预览，本轮把它的规则表并入这个共用模块，两处调用同一份字典；不许两套规则并存。#31 在途未提交，先读后改。

### 第二步 · 查重指纹升级（正文骨架＋公式签名＋置信度）

1. 判重不再直接拿原始源码算指纹，改为**比对归一后的源码**。
2. **正文骨架**：把数学段整段挖掉、按顺序留占位，只留中文与标点，归一后算相似度（编辑距离／SimHash 均可）。
3. **公式签名**：把数学段里的数字／字母／运算符按顺序抽出来，忽略 `\frac`、`\left` 这类排版命令；**符号一个都不能省**（`\cap` 与 `\cup` 必须分得开）。
4. **置信度**：由确定信号加权（四要素指纹是否全等、骨架相似度、签名是否全等、数字是否一致、答案是否一致），输出档位标签（确定／很像／较像／可能）＋百分比；不是黑箱概率，措辞只说「很像」。每条要能展开列出命中/未命中的信号。
5. 现有「高度相似 0.92」口径（`app/core/pending_dedupe.py`）要么并入新分档，要么明确退役，不许两套尺子并存；退役须在回传单写明调用点。
6. 不改主库正文；指纹可预存/缓存，改题时重算。

### 第三步 · 整批入口初查（从「只报数」改成「产出重题候选」）

1. 批次解析完成后，后台自动跑整批查重（复用现有 `warm_dedupe_scan` / `warm_batch_scan` 壳，不另起一套）。
2. 判重口径按第二步执行，**默认最宽档**（宁多不漏）。
3. 命中的题从审核画布**抽出**，进入重题池；未命中的正常审。抽走发生在老师开始看之前，纸带不得跳动。
4. 初查结果要能撑过底座重启（落盘或可在重启后重算，第四步定），不许一重启就假装「没重复」。
5. 主库读不通时如实报「初查失败、可重试」，绝不当成「没有重复」。
6. 抽走即**搬移**：题目文档与它自己的成品图从待审池搬进池子，批次里不再留一份；搬移失败要回滚，绝不出现「池里有了、批次里还留着」或反过来的半截状态。

### 第四步 · 重题池数据与接口（跨批次）

1. **存储**：池子独立于待审池与批次（表名与放置按 R03 定）。每条自带题目文档、自己裁下来的成品图、来源批次号与文件名（只作溯源）；**不存整页底图**。批次删了，池里那条照常可读。
2. **一条一题**：池内一条进来题只占一条，配一条最像的主库原题，不做分组、不做折叠。
3. **读接口**：列表＋每条的两侧完整文档（供纯渲染对比）＋置信度标签/百分比/信号明细＋当前档位；支持按档位取候选。
4. **四个动作接口**：`merge_metadata` / `add_solution` / `keep_separate` / `delete`，语义按本卡第二节。
   - `merge_metadata`：只并元数据，题面与答案不动；冲突字段不覆盖，返回冲突清单。
   - `add_solution`：解析并成新解法（复用现有「解法二」写法）＋追加来源；答案明确不同则拒绝。
   - `keep_separate`：当独立新题写库，复用 `pending.approve` 的校验（答案、占位符、考向）；校验不过不写库、留池并返回缺失项。
   - `delete`：只删池内这条与它的成品图，主库不碰。
5. **终局闸门**：`pending.approve` 里的精确判重保留，防前端绕过；`keep_separate` 必须走显式动作参数，不许靠删掉闸门实现。
6. 裁决完这条从池里退场；拖档重扫不得复活已裁决条目。
7. 所有动作写一条最小审计（时间、动作、来源批次、主库题 id），供回传单对账。
8. 两个 `plugins.json` 若涉及命令白名单，发版前必须全等。

### 第五步 · 重题池画布与交互

1. 重题池有**自己的画布**：左＝主库原题、右＝池里这条，**纯渲染对比，不比源码**；画布里一颗按钮都不许有（军令 #23），按钮住辅助栏。
2. 每条显示置信度标签＋百分比，默认按像的程度排序；能展开看「为什么像」的信号明细。
3. 档位三档：**严／标准／宽**；默认**宽**；拖档即时重扫；档位不落盘（本会话有效，不加配置项）。
4. 四个动作：**合并元数据 / 新增解析（增加来源）/ 不重复（分开存） / 删除**。答案明确不同时前两项锁住；删除二次确认；`keep_separate` 校验不过时留在池里并列出缺什么。
5. 审核画布的红灯**退出**，只留青黛（悬停）与琥珀（有问题）；池里的题不参与【全部入库】、不参与整批扫灯。
6. 空池留白，不留占位文案。
7. 批次删除与池子互不影响：删批次不删池，删池不碰批次。
