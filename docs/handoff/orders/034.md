# 军令 #34

【命令七｜基于身份特征的清场启动（单实例 + 全局清理）】

背景：老师提出更聪明的方案。摒弃盲目顺延端口，也不按文件夹杀进程。改为基于“特征身份”的精准清理。

目标：不管在哪个目录点、点多少次，最终后台永远只有当前启动的唯一一个服务。

要求：
1. 实现“单实例锁”：
   启动器启动时，先从 65496 开始往上探测（或读 data/.current_port），请求 /healthz。
   如果发现返回 "jiuzhang-operator"，且当前执行路径就是本目录：
   -> 说明服务已经跑起来了，直接把该端口传给浏览器拉起页面，然后直接退出，绝不启动新进程。

2. 实现“跨目录精准清场”：
   如果发现已有的九章算子服务，但当前执行路径不是它的所在目录：
   -> 说明用户换了新目录（或者想强制刷新）。
   -> 根据该端口找到占用它的 PID。
   -> 强杀该 PID（taskkill /F /T）。
   -> 循环清理，把扫到的所有九章算子旧进程全部干掉。

3. 启动最新服务：
   清理干净后，统一在 65496 端口拉起最新的服务（如果被别的不认识的程序占着，才报错）。
   启动成功后写入 data/.current_port，拉起浏览器。

4. 测试契约更新：
   更新 test_version_consistency.py，必须包含 healthz 身份校验、端口探测、强杀 PID 的逻辑，移除原先按路径匹配杀进程的代码。

## 边界

- 不得扩大改动面；发现与 `docs/AGENTS.md` 冲突先停下报告。
- 涉及前端必须在浏览器里走真人路径；涉及插件必须过三查。
- 一个阶段一个 commit，测试不绿不许 commit。
