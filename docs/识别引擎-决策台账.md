## 一、项目定位（一句话）

九章算子是一个**纯本地、免注册、插件化**的数学题库底座：底座只管鉴权、导航、数据总线、插件生命周期；
录题、题库、组卷、讲义全部是插件。本台账的目标：**给底座加上"识别引擎"能力**，把切好的单题图
转成 Markdown + LaTeX，并且能装本地引擎、走云端兜底。

## 三、决策台账

| 编号 | 决策 | 理由 | 状态 |
|---|---|---|---|
| D1 | AGPL/GPL 模型**可以**进候选池 | 老师在自己机器上本地安装、个人使用，不构成我们分发 | 已定 |
| D1a | 但插件包内**绝不打包**二进制或权重，只放上游 URL + SHA256 | 一旦打包就从"提供接口"变成"我们分发"，AGPL/GPL 义务上身 | 已定（硬边界） |
| D2 | 允许多个 Python 环境共存 | 相互隔离即可，磁盘不是问题 | 已定 |
| D2a | 隔离五条：独立目录（**= 底座根下 `engines/<id>/`，与 `.venv/` 平级，底座升级不覆盖**）/ 不碰 PATH / 缓存各归各 / 解释器版本钉死 / 进程端口归底座 | 实测冲突源：`start.bat` 用 `py -3` 不钉版本、onnxruntime 三种发行包同名、CUDA DLL 互踩 | 已定 |
| D3 | 安装不设门槛，三态 `ready / degraded / blocked`，只有 blocked 拦安装 | 老师可能升级电脑，先装后用是合理需求 | 已定 |
| D3a | 装完当前跑不动：调用时自动走云端，提示"本地加速不可用" | 不允许静默，否则老师以为在用本地、实际出网 | 已定 |
| D3b | 体检结果**可重算**，换机器自动翻档 | 不许把体检缓存成永久结论 | 已定 |
| D4 | 只做**数学**；物理化学后置 | 化学结构式、电路图不是公式问题，是图的问题 | 已定 |
| D5 | 一道题只用一个模型 | 多模型投票无成熟实践，且会破坏"全局统一写法"（pipeline 第 49 条） | 已定 |
| D6 | 图片输入也**先切题、再逐题送模型** | 整页送模型会被压缩到 1024 宽，公式必糊；单题图则被放大，不损失 | 已定（**覆盖 pipeline 文档第 17 条**，2026-11-18 已回写该文档） |
| D7 | 图片切题 = 本地轻量 OCR + 复用 PDF 的题号链；YOLO 降为辅助 | YOLO 是区域分类器，不认题号；题号链才是"题从哪到哪" | 已定 |
| D8 | 一页 0 或 1 个题号 → 整页当一道题；≥2 个 → 切 | PDF 与图片共用同一条判据，不特判"单题/整卷" | 已定 |
| D9 | 几何图形必须抠出来存 `images[]`，正文留注释锚点 | 图形不能用文字替代；VLM 只会描述图，不会保留图 | 已定 |
| D9a | 入库只存四类图：题干 / 选项 / 答案 / 解析；**整题截图不入库** | 整题截图与文字内容重复，且入库即已审核 | 已定 |
| D10 | 契约 `IMAGE_ROLES` 缺 `answer`，等抠图那步一起加并升 `schema_version` | 四类图缺一；合并做少一次版本变更 | 已定（未实施） |
| D11 | 公式输出必须过清洗器 + MathJax 渲染校验；失败标"待核"，不许入库 | `jzo_mathjax.js` 已有失败判定（红色 mtext 也算失败） | 已定 |
| D12 | 文本型"就地替换"，不拼；图片型"一个模型一次出混排"，不拆 | 拼装是最大误差源：文字与公式分离识别后无共同坐标系 | 已定 |
| D13 | `.doc` / `.wps` 走 COM 转换，超时 30 秒放弃，禁宏 | 老师机器基本都有 Word/WPS；不打包 LibreOffice | 已定（未实施） |
| D14 | 答案/解析与题分排（版式 1/2/3）：题区、答案区**各切各的题图**，两张题图都只作识别中间产物、**不入库**；识别结果按题号并回**同一条题目记录**——题干进 `stem`、答案进 `answer`、解析进 `solution`，几何图按所属区块进 `images[]` 并标 `role`；**禁止把两张题图拼成一张长图** | 契约里没有"整题长图"的位置（`app/core/question_contract.py:314–324`）；D9a 禁整题截图入库；拼装是最大误差源（D12），两截隔页、缩放与页边都不同，拼出来的图既非原卷也不可核 | 已定（2026-11-17 主公确认三层口径） |
| D15 | 跨页题：**同一道题的上下两段允许纵向拼接**成一张题图，四条件缺一不可——① 同题同卷 ② 同一 dpi 渲染 ③ 页宽一致 ④ 拼接处留 8–12px 缝；两段原图与两段坐标必须同时留存可追溯。**这是对 D14 的限定，不是推翻**：D14 禁的"题干图与答案图跨章拼长图"照旧禁止 | 素材实测跨页题占 12.5%（第 1 页 8 题中第 8 题的四个选项在第 2 页顶部）；不拼就丢选项；同题、同页宽的纵向叠加有共同坐标系，误差源远小于跨章拼图（D12） | 已定（2026-11-17 主公裁） |

### 7.2 卷子版式与题号轮次（2026-11-17，主公口述 + 实测）

**版式清单（6 类，且不可穷尽）**（第 5 类"答案与原题分两份文件存"本期不纳入，属少数）：

| # | 版式 | 后段形态 | 对切题链的影响 |
|---|---|---|---|
| 1 | 前题 + 后答案 | 只给答案，无解析 | 答案区的题号会再走一轮 |
| 2 | 前题 + 后「题干 + 解析」 | 后段重述题干，再给解析 | 题号与题干双重复，会切出重复题 |
| 3 | 前题 + 后混装 | 先给选择/填空答案；大题有的给解析、有的写「略」 | 题号与「略」混排 |
| 4 | 只有题 | 无答案、无解析 | 单轮题号，最干净 |
| 5 | 答案与原题分两份文件 | — | **本期不纳入** |
| 6 | 每题紧跟答案与解析 | 题后紧跟 `【答案】` `【解析】`（解析正文常带「1．2．3．」列表编号） | 题号只一轮；但解析里的列表编号会污染题号链（实测"轮=3"多为这类误判） |

> **版式不可能穷尽**（2026-11-17 主公判语："本质上这个版式类型无穷无尽"）。所以本表只是**验收抽样的分档标签**，
> 不能当代码分支的依据——切题链必须按不变量走（见 D15）。

**实测（62 份 A1，`pypdfium2` 文字层，按"题号序列是否重置"初判）**：单轮约 19 份，两轮及以上约 43 份。
初判有明显误取（峰值出现 86 / 67 / 68，如 `1.86` 被当成题号），所以**自动判别只能筛、不能定档**。
可确认的结论只有一条：**多数卷子的题号不止一轮**，D8 的「0 / 1 / ≥2」不足以覆盖答案区。

**判据漏洞（须修）**：`哈尔滨市六校2024-2025学年高一上学期期末联考试卷(含答案解析）.pdf`（8 页 / 6451 字）
题号只命中 1 个（密度 0.1/页），另有密度 0.4、0.6 各一份。按现行 A1 判据（每页 ≥300 字且题号 >0），它们
会被当成"文字层可切"，实际题号链基本取不到——**A1 必须加题号密度下限**（阈值待定）。

> 作废说明：本节原先以文件名（含答案/解析）当版式判据、称"104 份含解析"，已由实测推翻——文件名不代表版式结构。
